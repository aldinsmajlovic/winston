# Lockdown Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A lockdown switch: while on, every action asked in a guarded conversation waits for your phone, guarded conversations know nothing private, and winstond answers only his own computer.

**Architecture:** The state is a file in `data/` that every process reads (`core/lockdown.py`). The brain's tool wrapper (`_no_repeat` in `core/brain.py`) hands a guarded action to winstond (`POST /api/lockdown/hold`), which turns it into a `Pending` with a `run` callable, sends the phone notification and runs it on approval. winstond's middleware closes the UI to other devices, and the prompt leaves memory, the diary and extensions' data lines out.

**Tech Stack:** Python 3 (FastAPI, Pipecat, httpx, pydantic), `uv`; web UI in React + shadcn (`web/`); checks are script-style `tests/*_cases.py` with `harness.expect`.

**Spec:** `docs/superpowers/specs/2026-11-27-lockdown-design.md`

## Global Constraints

- Work on a branch or worktree (`superpowers:using-git-worktrees`). `main` has your own uncommitted edits (`src/winston/core/memory.py`, `src/winston/core/spoken.py`, several docs): never stage them, never edit `core/memory.py`.
- Commits are signed off: `git commit -s`. End each message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No em dashes anywhere; `just lint` checks.
- No personal data in code, tests, docs or screenshots: entities in tests come from `tests/fake_ha.py`.
- Guarded places: `voice`, `satellite`, `assist`, and any conversation in a room. Trusted: `web`, `discord`, `text` outside a room.
- His reply while waiting: "needs your confirmation first, on your phone, within five minutes. Nothing has happened yet." Refused: "Not available right now. Nothing has happened." He never names you or says why.
- Phone notification text starts with `Lockdown: `.
- "His computer" means `secrets.this_computer(request)`: a loopback client and a Host header in `LOCAL_HOSTS`.
- Fail closed: a lockdown file that exists but cannot be read counts as on.
- A change is not done until the docs say it exists (`docs/writing-docs.md`).

## Review Focus

1. **A trusted conversation while locked down** (a Discord DM outside a room) runs actions at once, with memory in its prompt. Pinned in Task 4.
2. **Lockdown turned on mid-conversation:** a session built before it holds its next action anyway, since the gate reads the file on every call. Pinned in Task 4.
3. **Home Assistant tools are wrapped twice** (`_scope_by_name` re-registers, so `_no_repeat` wraps the outer handler too): one held call must make exactly one `Pending`. Pinned in Task 4.
4. **winstond unreachable while locked down:** the gate answers with the refusal and never runs the tool. Pinned in Task 4.
5. **"Lockdown off" from a local process with a channel** (the voice subprocess is loopback) waits for the phone; only a call without a channel turns it off at once. Pinned in Task 2.

**Interfaces:**
- Produces, in `winston.core.lockdown`:
  - `GUARDED = ("voice", "satellite", "assist")`
  - `PASS = frozenset({"start_over", "mark_mistake", "lockdown"})`: tools that run whatever the state
  - `WAITING: str`, `UNAVAILABLE: str` (the exact sentences in Global Constraints)
  - `state() -> dict | None`: `{"since": float | None, "by": str}` or None when off; reads `resolve("lockdown.json")` on every call, no caching
  - `on() -> bool`
  - `turn_on(by: str) -> bool` and `turn_off(by: str) -> bool`: False when already in that state; each appends `{"ts", "on", "by"}` to `resolve("logs/lockdown.jsonl")`
  - `guarded(place: str, in_room: bool) -> bool`: `place in GUARDED or in_room` (independent of `on()`)
  - `windows(start: float, end: float) -> list[tuple[float, float]]`: the on periods overlapping `[start, end]`, from the log; an open one ends at `end`
- Produces, in `winston.api.secrets`: `this_computer(request: Request) -> bool`

**Interfaces:**
- Consumes: Task 1's `lockdown` module.
- Produces:
  - `Pending(ext_id, tool, args, label, channel, nudge=None, run: Callable[[], Awaitable[dict]] | None = None)`. `Host.confirm` calls `p.run()` when set; the result has the same shape as `call_tool`'s (`{"ok", "result" | "error"}`).
  - `Host.add_pending(p: Pending) -> None` (public, same behaviour)
  - `brain_tools()` rows gain `"private": bool`, true when the extension's manifest `permissions` has `memory`
  - `api/lockdown.py`: `router(app: FastAPI) -> APIRouter`, reading `app.state.extensions`, `.rooms`, `.supervisor`, `.feed`, `.cfg`:
    - `GET /api/lockdown` gives `LockdownState{on: bool, since: float | None, by: str | None}`
    - `POST /api/lockdown` with `{on: bool, channel: str | None}` gives `LockdownAnswer{on: bool, waiting: bool, note: str | None}`. On: always at once. Off without `channel`: at once. Off with `channel`: a `Pending("lockdown", "off", {}, "Lockdown: turn off", channel, run=...)`, answer `waiting: true, note: WAITING`.
    - `POST /api/lockdown/hold` with `{name: str, args: dict, channel: str}` gives `{"waiting": true, "note": WAITING}` or `{"error": UNAVAILABLE}`. It resolves `name` as an extension tool (`host.brain_tools()` by name) or a Home Assistant tool (a name in a row of `await HomeAssistant(cfg).tools()`). Anything else is refused and nothing is queued. Labels: `f"Lockdown: {title}: {tool_title}"` for an extension tool, `f"Lockdown: {row.label}: {', '.join(map(str, args.values()))}"` for Home Assistant. The run is `host.call_tool(ext, tool, args, confirmed=True)` or `HomeAssistant(cfg).call_tool(name, args)` (text starting "Error" means not ok).
  - `set_lockdown(app, on: bool, by: str) -> None` in `api/lockdown.py`, the one place a change happens. It calls `turn_on`/`turn_off`, then `rooms.clear` on every room, restarts the `voice` item when it is running (`sup.stop`, then `sup.start` in a task, as `/api/engines/{name}/restart` does), and publishes a feed event of type `"lockdown"` (`{on, since, by}`).

  - **Review Focus 5:** `POST /api/lockdown {on: false, channel: "voice"}` gives `waiting: true` and it is still on. Approving that confirmation turns it off. Then on again, `POST {on: false}` with no channel turns it off at once.

  - The `lockdown` tool: one argument `on: boolean`. Description: "Turns lockdown on or off. On, actions wait for the owner's phone and he keeps private things to himself; anyone may turn it on.
