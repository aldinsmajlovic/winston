# Decisions

One line per deviation from `WINSTON_PLAN.md`: date, what changed, why.

- 2026-09-22: Renamed the project from Jarvis to Winston (Aldin). Consequence: openWakeWord and microWakeWord ship a pretrained "hey_jarvis" model but nothing for "Winston", so M3 needs a custom-trained wake word model. The plan's factual mention of HA Voice PE shipping "Hey Jarvis" is kept as is.
- 2026-09-22: Repo created at `~/ai/winston` on a machine with an RTX 3090 (24 GB), 16 CPU threads, 31 GB RAM, Arch (zen kernel). Whether this is the dedicated brain box or the main PC is still an open question (plan §8).
- 2026-09-22: Development runs on Aldin's main PC (the RTX 3090 machine this repo lives on). A dedicated brain box will be bought when the project is done or nearly done. Consequence: the GPU is shared with other work (ComfyUI etc.), so services must be start/stop scripts rather than always-on, and VRAM budgets in plan §4 apply only while nothing else runs.
- 2026-09-22: M0 serving stack: vLLM 0.29.0 via Docker (`vllm/vllm-openai:v0.29.0`, 30 GB image) with `ops/docker-compose.yml`, as the plan suggested. Compose uses `runtime: nvidia` instead of Docker's `--gpus` device path because this host's CDI spec (`/etc/cdi/nvidia.yaml`) references a driver library that no longer exists; the root fix is `sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml`, not needed for now.
- 2026-09-22: Local LLM weights: `QuantTrio/Qwen3.5-9B-AWQ` (no official Qwen quant exists for the 9B). It quantizes only the MLPs to INT4 and keeps attention, layer 0 and the vision tower in BF16, so weights take ~11.4 GB, not the 6–8 GB in plan §4. Set `--gpu-memory-utilization 0.70`: 16 GB total, 3.2 GB KV cache (93K tokens). Alternatives if VRAM gets tight at M2: `mssfj/Qwen3.5-9B-GPTQ-INT4`, or Qwen3.5-4B.
- 2026-09-22: Tool-call parser: `qwen3_coder` with `--reasoning-parser qwen3`, per the official model card; passed M0. Community reports (NVIDIA forums, vLLM issue #36769) say `qwen3_xml` is more robust over long agentic sessions; switch if tool calls degrade at M1/M4. MTP speculative decoding left off for the same reason; test it at M2 for latency.
- 2026-09-22: Model slot check: Qwen3.8 (Aug 2026) shipped only 27B and larger; no official Qwen3.6/3.8 dense 9B exists, so Qwen3.5-9B stays. Qwen3.8-27B AWQ needs ~21.5 GB on a 3090 and belongs to the phase-2 bigger-brain option.
- 2026-09-22: Milestone order changed: M2 (voice round trip in the browser) comes before M1 (Home Assistant). Aldin: "you can't HA or anything before you know the core is working." M1 needs HA credentials anyway.
- 2026-09-22: M2 stack as planned: Pipecat 1.11.0 with its SmallWebRTC transport and prebuilt browser client (`pipecat-ai-prebuilt`; the older `pipecat-ai-small-webrtc-prebuilt` package no longer matches the runner's import). Silero VAD, `stop_secs` 0.3.
- 2026-09-22: STT: Parakeet TDT 0.6B **v3** (multilingual) rather than v2, via `onnx-asr` INT8 on CPU. Word-perfect on VCTK test clips, ~0.6 s for 12 s of audio on the 5800X. Loaded once per process (`load_parakeet`), not per connection.
- 2026-09-22: TTS: Chatterbox-Turbo in its own Python 3.11 venv (`voice/tts/chatterbox_server`) behind an OpenAI-compatible `/v1/audio/speech`, so Pipecat's stock `OpenAITTSService` consumes it. Two gotchas: its `perth` watermarker needs `pkg_resources`, so `setuptools<81` is pinned; and it has no streaming API, so audio is generated per sentence (Pipecat already sends sentences). Measured: 3.1 GB VRAM, ~0.3 real-time factor, 325–400 ms for a short sentence, ~1.2 s for an 80-character one.
- 2026-09-22: Default voice: VCTK speaker **p254** (male, Surrey), picked by Aldin from six samples ("sounds pretty good and natural"); p232 was the interim default. CC BY 4.0, attribution in `voice/tts/README.md`. Five other British male VCTK clips are in `voice/tts/reference/vctk/` for Aldin to compare; none is a cloned actor. Swap for a consented custom clip whenever wanted.
- 2026-09-22: Home Assistant (2026.7.2) wired up by API with Aldin's owner token in `.env`: MCP Server integration created via the config-flow API; its Streamable HTTP endpoint is `/api/mcp` in this version, not `/api/mcp/assist` as the plan said. 11 tools (HassTurnOn/Off, HassLightSet, GetLiveContext, GetDateTime, todo, timers, broadcast).
- 2026-09-22: Exposure is a strict allowlist enforced by `ops/ha_expose.py` (13 entities with plain-English aliases; HA had auto-exposed 26 more, all Plex clients and Adaptive Lighting switches, now un-exposed and auto-expose turned off). Token is owner-level for development; Aldin will revoke it and issue a dedicated Winston user's token later (plan §6 rule 5).
- 2026-09-22: "Boot my PC": created a `wake_on_lan` entry for the Arch PC's MAC, with the broadcast address of the PC's subnet. HA makes it a *button*, not a switch, because no host was given for state. HA and the PC sit on different subnets, so the directed broadcast must cross subnets; untested until the PC is actually off, and it needs WoL enabled in BIOS.
- 2026-09-22: No TV or camera integration exists in HA yet (the 22 media_players are all offline Plex clients). "Turn on my TV" and M5 need a real integration (Samsung/LG/Android TV or an IR blaster) first; Aldin's call.
- 2026-09-22: Brain sampling for tool use: temperature 0.3 and presence_penalty 0 instead of Qwen's chat defaults (0.7 / 1.5). With the chat defaults the 9B often announced an action ("I'll set the lights…") and stopped without calling the tool; with these, 12/12 trial commands called the right tool. The persona also says "call the tool immediately, speak only after the result".
- 2026-09-22: Pipecat 1.11 gotcha: `OpenAILLMService(system_instruction=...)` is silently ignored when `settings=` is also passed; the persona must go inside `OpenAILLMService.Settings(system_instruction=...)`. Cost an hour of "why did the model get dumber". Also migrated `PipelineTask`/`PipelineRunner` (deprecated since 1.3) to `PipelineWorker`/`WorkerRunner`.
- 2026-09-22: HA's GetLiveContext name filter needs an exact alias match, and the 9B likes to filter by short names ("phone"), so aliases now include the short forms people actually say. Whole-home context is only ~1.4 KB for 13 entities, so unfiltered calls are fine too.
- 2026-09-22: Voice + tools measured headless: a read-only tool turn ("phone battery") reaches first audio in 1.6 s; a light-changing turn took 7.5 s because HassLightSet blocks until the Zigbee group confirms (2–6 s, HA-side). Follow-up for M2 polish: speak a short acknowledgement ("On it.") when a state-changing tool has not returned within ~700 ms, via Pipecat's function-call start hook, instead of loosening the act-first rule.
- 2026-09-22: First hallucinated action: on "change the temp of the lights and check my phone battery", the 9B did two GetLiveContext reads and then *said* it had set the lights warm without calling HassLightSet. Read-then-act chains are where it drops the act. Mitigations in order: keep persona rules to one hop (ask for a missing value rather than infer it from state); add a claim guard (reply claims an action but no state-changing tool ran → automatic correction); enable thinking mode on the text channel where latency matters less; and this is the trigger the plan names for the phase-2 bigger brain (Qwen3.6-35B-A3B / Qwen3.8-27B).
- 2026-09-22: Thinking mode is per channel: off for voice (`llm.enable_thinking`), on for text (`llm.enable_thinking_text`, used by the CLI and later Telegram). On "change the temp of the lights and check my phone battery", the 9B without thinking asked the question and skipped the battery 3/3; with thinking it checked the battery and then asked 3/3, at ~7 s per turn instead of ~3.5. Single commands are unaffected. Voice keeps the one-hop persona rules and lower ambition until the bigger brain.
- 2026-09-22: Winston reported a phone battery of 81% while Aldin's phone read 64%: HA's live context has no timestamps, the Pixel's reading was 5 h old and the OnePlus sensor had been dead for 29 h. Added a local read-only tool `get_phone_battery` (`brain/tools/ha_state.py`) that returns every phone with the age of its last report, and the persona now says how old a reading is. Rule for future sensors: never surface a value without its age.
- 2026-09-22: Winston will be open source at github.com/aldinsmajlovic/winston under **Apache-2.0** (Aldin weighed AGPL to block closed forks against reach in a permissive ecosystem, HA/Pipecat/vLLM, and chose reach). DCO sign-offs, no CLA. Trademark note in CONTRIBUTING.
- 2026-09-22: Architecture for the open-source shape (see docs/architecture.md): one control service `winstond` (FastAPI, REST + SSE) that supervises engines (docker / subprocess / external drivers) and serves the web UI; typed, versioned config with a data directory holding everything personal; adapters, tools and channels as plugins with small contracts; standard protocols at every seam (OpenAI-compatible LLM and TTS, MCP for tools). Personal specifics (entity aliases, phones, phrasing hints) move from code to config and persona.
- 2026-09-22: Web UI stack: React + Vite + TypeScript with shadcn/ui, Tailwind and lucide icons, JSON-Schema forms generated from the config schema, OpenAPI-generated client. Aldin's rules: component library over hand-rolled CSS, icons over text, no text where it does not belong, no em dashes, none of the usual AI design pitfalls. Guardrails in docs/ui-guide.md.
- 2026-09-22: TV control deferred indefinitely; Aldin has no TV. The plan's "turn on my TV" example stays as a future capability.
